# PARIS 设计适配与持续迭代

0.7网页已切换为单XGBoost设计适配，数据与训练方式见[SINGLE_XGB.md](SINGLE_XGB.md)。下文记录历史多分支训练器，原有模型及实验仍保留。

模块位于“PARIS 迭代”。输入是某个设计逐渐累积的实测训练集；输出是该设计的新权重、固定候选验证报告、版本记录和可回退的当前版本指针。

这里的适配是**完整 PARIS4.0 架构的设计专属重训**，不是神经网络的增量梯度更新，也不是把 native 简化后端改名。参考原版模型库提供原始实现和冻结配方，所有拟合权重使用本设计训练候选重新估计。

## 日常操作

1. 在输入页/CLI完成GR特征采集与实测DR标签整理；进入迭代页选择累计数据目录。
2. 选择含完整训练实现的原版模型库，检查数据，选择design与参考配方。
3. 首次训练固定留出验证候选，其余候选用于重训。后续使用包含旧样本与新增样本的累计数据集，已有验证候选始终排除在训练外。
4. 查看新版本、GR与可比较的当前版本在同一固定候选上的结果。
5. 验证通过后手动启用或导出权重；变差的版本保留报告，继续使用当前版本。已通过的历史版本可以回退，启用日志保留前后指针。

不会自动启动新的detailed-route，不会在训练完成时自动切换生产模型。增加样本可能改善、持平或降低表现；旧版本保留与启用门禁是工程策略，不是泛化性能保证。

## 数据契约

目录需要以下六个文件：

| 文件 | 用途 |
|---|---|
| features.parquet | 完整原版候选CTS/GR描述与104维端点摘要；不含DR/目标字段 |
| source_sink.parquet | GR-only线网连接及原版完整电气输入 |
| net_load.parquet | GR-only π-model R/C与负载 |
| labels.parquet | design、candidate_id、实测 final_tns（ns，非正） |
| wire_labels.parquet | design、candidate_id、net_name、driver_pin、sink_pin、transition、corner、实测 dr_wire_delay |
| PARIS_TRAINING.json | PDK、流程、角点、标签/特征版本、单位与用途声明 |

界面可下载说明模板：

```json
{
  "version": 1,
  "pdk_id": "your-pdk-version",
  "flow_id": "your-verified-flow-version",
  "corner": "nominal",
  "label_version": "measured-labels-v1",
  "feature_version": "original-full-gr-v1",
  "time_unit": "ns",
  "label_source": "measured_dr_sta"
}
```

这份声明不是物理闭合证明。数据构建者仍须核验精确Liberty、SDC、STA角点/单位和final TNS来源；不能把模型伪标签或不一致的DR重放值当真值。当前训练器要求每个训练候选都有匹配的实测线网标签，不会因为只有TNS标签就悄悄跳过线网模型。未匹配的GR弧可由已匹配的历史弧训练出的模型预测，实际覆盖率写入训练协议。

最少36个有实测标签的候选，训练至少24个、固定验证至少12个。首次按候选ID的确定性散列留出max(12, ceil(20%N))个候选，之后不随样本增多重新划分。标签、验证GR内容改变，需要新的label_version/feature_version或流程版本，不能静默更改原验证协议。候选级隔离不能保证相近分割、共享网表派生候选完全独立。

当前接受**累计数据目录**，不在网页里自动合并多个增量批次；旧训练候选或固定验证候选从后续目录消失时会阻止训练。每次冻结输入哈希和角色，原始数据只读，避免重复复制大规模GR输入表；只写训练标签快照和本轮模型/验证产物。建议为累计数据使用独立版本目录，保留旧GR源表；仅记录哈希不能恢复被外部覆盖的原始文件。

## 完整架构与训练协议

新权重算法标识为 `paris4.original.design-refit.1`，区别于原版七设计封存模型 `paris4.original.seed17.1` 和精简自训练 `paris4.native.1`。

重用参考包内的原始v2/v3、PARIS ranking、timing_predict实现：

- 原版XGBoost线网DR delay残差模型：按候选隔离的5折交叉拟合构建训练侧线网摘要，最终用全部当前训练弧重训；保持原参数（900棵树、depth4、learning rate0.01等），2CPU。
- 原始候选模型与预处理：通过原版 `baseline_fit` 重训；候选纠错使用原版 `baseline_oof`、`Correction` 与 `CorrectedPARIS`。
- 阶段共识：沿用参考配方的CTS/GR融合规则。
- 端点分支：克隆参考端点估计器并在本设计训练候选上重训，对GR log-cost残差学习；沿用参考配方的融合权重。
- 如果参考配方有legacy增强分支，保留该分支并在当前累计训练池重训；不引入参考设计的训练标签。

当前版本**冻结参考配方的纠错规格/权重、阶段共识和端点融合决定**，不根据本轮开发验证分数重新挑配方或调权重。它更新拟合权重，不保证这份参考配方对新设计最优。新设计默认取原版库中字典序首个参考配方，用户可在训练前明确选择来源；参考配方变化是另一条协议，不能把跨协议分数当成同验证集学习曲线。后续可以升级训练策略，但需新算法版本和明确验证协议。

训练子进程仅接收筛选后的训练标签、训练线网标签和GR输入位置，不接收验证TNS数值。模型封存后，另一个子进程仅读取固定验证GR并封存预测，再由独立评分步骤读取验证真值。训练回执记录实际候选ID、折隔离、输入哈希、配方和模型签名。

## 评测和启用

显示Kendall tau-b，以及Top-1真值遗憾（ns）：预测第1名候选的真实TNS成本与真实最优候选之差，并列第1名取平均。相对排序分数不能作为TNS预测，所以不计算这种分数的“TNS MAE”。

启用要求：至少12个验证候选；tau-b有效且不低于GR与可比较当前版本；Top-1遗憾也不高于它们。持平可启用，但不标为提升。该启发式门禁不是统计置信保证。

初次参考模型没有该设计权重，或其训练集合与当前验证候选重合，原因保存在验证报告和日志中，该模型不进入对照表。已启用的本协议版本若无法在固定验证池比较，后续验证会停止，不降级成只比较GR。

开发验证集在迭代时反复可见，不能称独立测试。正式验收应另留未被迭代查看、也未进入任何模型训练的新候选/新批次，冻结整个方法后再测试。模型未启用不代表已独立证明不优，启用也不代表对未来候选必然提升。

## 使用适配权重

“启用”更新迭代模块中该设计/流程的当前版本，作为后续验证的比较基线；不会暗中替换其他设计或用户已经明确选择的预测模型。每个通过验证的版本可从网页导出 `.tar.gz`，或选择“在预测页使用”把该权重明确交给预测入口。原版模型库不会被覆盖。新版本仅支持其design和记录的工艺流程。

目标GR特征目录还需要 `FEATURE_CONTEXT.json`，包含与权重MODEL_CARD中一致的 `pdk_id`、`flow_id`、`corner`、`feature_version`、`time_unit`；这里不需要标签。GUI预检查与导出包的预测入口都会核对这些值，不能仅因列名相同就把其他工艺的数据交给本模型。

```bash
paris model import --input PARIS4-my_design-VERSION.tar.gz --output imported
paris predict --model imported --dataset new-gr-inputs --output ranking.parquet
```

部署输出仍是批次相对排序，不是物理闭合的DR TNS。旧封存模型与旧485候选记录保持不变。

## 工程验证记录的含义

`purpose: "engineering_smoke"` 用于软件流程检查。即使分数很好，这类版本也被禁止启用/部署导出。当前真实历史工程验证可对线网做明确抽样以快速覆盖完整训练/加载/预测链；它不是新design泛化证据，也不是原版精度重现实验。单元测试用微型夹具验证划分、门禁和回退，不作为精度证据。
