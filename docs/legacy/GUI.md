# PARIS 可视化工作台

0.7网页默认使用每个design一个XGBoost；模型与迭代数据格式见[SINGLE_XGB.md](SINGLE_XGB.md)。评测页展示固定Open3DBench1000/200实验的CTS、GR与PARIS分数。

以下保留旧版完整模型入口的历史说明。

界面聚焦三个步骤：导入设计并准备特征，或选择已有完整 GR 特征 → 查看真实处理过程 → 获取全部候选的分数和排序。底层调用与 CLI 相同的 `paris predict`，不会切换到 native 自训练配方，也不在界面里增加新的训练或评测算法。

## 启动

在已安装完整 PARIS 环境的机器上运行：

```bash
paris ui --root /path/to/project --root /path/to/models \
  --workspace /path/to/ui-output \
  --model /path/to/imported-model \
  --dataset /path/to/original-gr-tables --open
```

然后在浏览器打开 `http://127.0.0.1:8765`。模型与数据参数可不填，进入页面后通过目录选择器选择；`--root` 指定允许浏览的目录，可以重复填写。默认只允许浏览启动命令所在目录。`--workspace` 使用新的空目录，或本工具已经创建的界面工作目录。

界面服务推荐部署在现有 Linux 推理环境中。浏览器不需要安装算法依赖。完整原版权重仍使用 `requirements-legacy.txt` 记录的环境；模型包与原版完整输入 schema 的要求保持不变。

远程服务器运行时，目录选择器浏览的是服务器目录。使用 SSH 转发在本机访问：

```bash
# 服务器上：
paris ui --root /path/to/project --root /path/to/models \
  --workspace /path/to/ui-output --model /path/to/imported-model \
  --dataset /path/to/original-gr-tables

# 本机上：
ssh -N -L 8765:127.0.0.1:8765 -p SSH_PORT USER@SERVER
```

## 1. 输入

选择完整原版 `paris4.original.seed17.1` 模型目录、导入目录或可信模型包，以及包含以下三个表的目录：

| 文件 | 内容 |
|---|---|
| features.parquet | 完整候选 CTS/GR 描述与104维GR端点摘要 |
| source_sink.parquet | GR线网连接、延迟、slew、几何与拥塞特征 |
| net_load.parquet | GR线网R/C与负载特征 |

点击“检查输入”，查看候选数量、设计数量、文件行列数和模型版本。格式缺失、DR/目标字段、未知设计或模型类型错误会显示具体原因。原版需要完整 schema，精简采集特征不会被填零或替代。

检查通过后点击“开始预测”。每次运行写入独立目录，输入与模型保持原状。

## 2. 处理

界面显示三个实际阶段：

1. 模型签名、输入格式与候选检查；
2. 调用完整原版线网预测、候选修正、阶段共识与端点融合；
3. 核对结果、生成完整排序和导出文件。

显示实际已用时间与运行日志，不编造百分比或子模块完成进度。当前服务一次执行一个预测任务。刷新网页不会重复启动任务。退出服务时，已启动的预测先完成；异常终止的部分输出保留，服务不自动重跑。

## 3. 输出

按 design 分别查看全部候选，可以切换设计、分页、查找候选 ID。

| 展示项 | 含义 |
|---|---|
| 排名 | 原模型输出的名次，保留并列 |
| 排序分数 | 批次相对成本分数，越小越好；悬停可查看原始精度 |
| GR TNS | 输入中的 GR 基线值，单位 ns |
| 较 GR 位次 | 原GR名次与模型名次的差异，不代表已验证的精度提升 |

导出 CSV/Parquet 包含本次全部设计与候选。Parquet保留原始分数与并列关系，是精确回归的推荐格式。运行目录包含原始推理 Parquet、带 GR 对照的 CSV、输入签名、阶段事件与日志。界面没有读取目标 DR 真值来展示“本次预测精度”。

## 数据边界

服务仅绑定本机回环地址；远程访问使用 SSH 转发。文件访问限定在 `--root` 目录内，接口使用会话令牌与同源校验。没有云端上传、外部字体或第三方在线脚本。预训练模型只能从可信来源加载。

原始网表/工程入口见 [数据准备说明](RAW_INPUT.md)：导入与缺项检查、受控流程编排、真实阶段日志/产物、特征目录和模型兼容性门禁。执行原始工程需要服务器绑定适配该工艺的真实流程，未配置时不会启动或宣称打通。底层完整原版推理算法保持不变。

## PARIS 迭代

侧栏提供设计适配：累计样本与实测标签检查、完整原版架构重训、固定候选验证、手动启用与回退、权重导出。说明与数据契约见 [ITERATION.md](ITERATION.md)。数据更多并不保证提升，当前版本不会被训练任务自动覆盖。
