METHOD / 方法介绍
PARIS 如何完成候选排序
先用布局、CTS 和全局布线结果估计详细布线后的时序，再把更值得运行 DR 的候选排在前面。

      
      

        
01
Shared feature extraction
把一个候选，整理成一份特征
同一个芯片的不同 3D 分割方案，就是不同候选。PARIS 从三个阶段提取信息，训练与预测使用同一套处理方式。
布局 Placement
看跨层连接、面积平衡、利用率和估计连线长度（HPWL），描述方案的空间结构与连线规模。
时钟树 CTS
看 TNS、WNS、端点时间余量（slack）和到达时间，了解早期时序表现。
全局布线 GR
看端点与关键路径的余量、单元和线网延迟（cell / wire delay）、信号变化快慢（slew）、电阻电容（R/C）和扇出；再结合拥塞、布线溢出（overflow）、线长与过孔（via）数量。
用均值、分位数和关键子集统计汇总：一个候选，对应一个特征向量。

        
02
Training
用实测结果，训练设计专属模型
把训练候选的特征与实测 DR TNS 配成样本，让一个 XGBoost 学习从 GR 到 DR 的时序修正。
模型综合判断：哪些结构、路径、电气量和拥塞组合，会让详细布线后的时序变好或变差。训练集内用 3 折交叉验证选择参数，为每个 design 保存一个模型。
候选特征 + 实测 DR TNS↓学习 GR → DR 修正↓当前 design 的 PARIS 模型

        
03
Inference
预测新候选，优先验证更好的方案
新候选完成 CTS / GR 后，加载本 design 的模型，预测它在 DR 后的 TNS，并对全部候选排序。
预测 DR TNS完整候选排序推荐 DR 候选
把排名靠前的候选优先送去 DR 实测，让算力集中在更有希望的方案上。

        
04
Feedback into the next round
让实测数据，进入下一轮迭代
记录新候选的 DR 结果，与它已有的特征配对，加入该 design 的训练集。保留已有训练样本，用累计数据重新训练。
每次都用同一批保留的验证候选比较新旧模型，排序效果更好时再更新。随着实测样本积累，模型持续适应当前设计。
M₁→M₂→M₃

  3. 预测其余候选
  4. 新增实测，继续更新

输入 → 处理 → 输出
PARIS 做什么
输入
已有完整 CTS/GR 特征可直接检查；原始网表或工程先进入预处理、分割、CTS/GR 与特征生成。原始工程需配套 LEF、Liberty 和 SDC，执行流程由服务器配置。
处理
汇总 CTS/GR 特征，由当前设计的PARIS模型 预测 GR 到 DR 的 TNS 残差，得到预测 TNS 和候选排序。
输出
预测 TNS、候选排序分数与排名。
支持范围
预测输入、训练数据和模型配置见项目文档。
